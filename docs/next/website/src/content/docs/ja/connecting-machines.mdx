description: Local と保存済み SSH マシンを 1 つの Herdr ウィンドウで操作し、エージェントをまとめて確認できます。各接続は独立して再接続します。

ローカルの作業とリモートのエージェントを、1 つの Herdr ウィンドウにまとめられます。SSH マシンを一度保存すれば、別のクライアントを開かずに、そのワークスペースと Local を切り替えられます。エージェント一覧には接続中のマシンが含まれ、作業場所や回答待ちのエージェントを確認できます。

各マシンは独自の Herdr サーバー、セッション、プロセスを保持します。1 台への接続が切れても、ほかの接続は切れません。

Herdr は、帯域が限られた接続で画面更新の通信量を減らすため、SSH 圧縮を要求します。互換性のある古い Herdr サーバーでも動作し、キー入力などの入力の届け方は変わりません。Herdr の `-C` オプションは SSH 設定の `Compression no` を上書きします。SSH が外部の ControlMaster を通じて既存接続を再利用する場合、その接続では元の圧縮設定が維持されます。

### SSH 認証の復旧

Linux と macOS で `remote.manage_ssh_config=true` の場合、マシン追加、サイドバー、API 操作は承認済み OpenSSH 接続を共有します。`herdr machine status [<label-or-id>] [--json]` は認証を求めず、現在の接続状態を確認します。**reachable** はリモート Herdr が利用可能という意味で、各 TUI の接続状態ではありません。ターミナルで `herdr machine reconnect <label-or-id>` を実行すると、SSH 認証後に保存済みマシンを検証します。インストールや更新は行いません。開いているクライアントは 30 秒以内に再試行し、再起動は不要です。**`! auth`**、**`! error`**、失敗後の再接続ステータスをクリックすると、最新のエラーと CLI コマンドが通知に表示されます。認証ポップアップは開きません。マシン行の展開・折りたたみは変更されません。

共有接続の `ControlPersist 600` はアイドル状態の 10 分を表すもので、MFA の有効期間ではありません。通信中の接続は維持されますが、企業ポリシー、SSH サーバー、ネットワークによってはそれより早く終了します。ローカル Windows の復旧はまだ対応していません。管理対象外の SSH 接続の認証は利用者の責任です。共有 ControlPath を使わずに `ssh` を実行するだけでは、Herdr の承認にはなりません。ホスト鍵の検証は緩和されず、未知または変更されたホスト鍵は引き続き **Attention** です。

## Settings で Remote を設定する

Remote は Settings の他の設定の後に並ぶ 3 つのタブ **remotes**、**images**、**account** で設定します（タブ行全体は `theme  indicators  sound  toasts  integrations  remotes  images  account` です）。右上にはサインイン中の hangar ユーザーが表示されます。狭いターミナルではタブ行がスクロールして開いているタブを常に表示し、隠れたタブは `‹` と `›` で示します。Remote のポップアップは、マシンの操作が収まるよう他のタブより数行高くなります。

**remotes** タブは Local、hangar マシン、SSH の Remote の順に一覧表示し、最後に **+ Add remote** を表示します。Remote には名前の前に `⇄` が付き（Local には付きません）、右端に状態を単語で表示します: **running**（緑）、**stopped** または **suspended**（薄色）、**starting…**、**stopping…** などの遷移中（黄）、**error**（赤）、**unknown**、SSH の Remote では **connected**、**disabled**、**offline** です。hangar に到達できない場合やサインインしていない場合は、最後に同期した状態として **offline** または **signed out** と表示します。**default** や **hidden** などの注記は状態の前に表示します。右側のペインには選択中の Remote が `name · hangar|ssh · state` の形式で表示され、その下に hangar が報告する場合はテンプレート、サイズ、クローン元のマシンや作成元のイメージ（エラー状態のマシンでは最後のエラー）が表示されます。その下に操作が 1 列で、空行で区切ったグループごとに並びます: **Start** または **Resume**、**Suspend…**、**Stop…**。次に **Test connection**、**Edit…**、**Use as default**、**Hide from sidebar**（または **Show in sidebar**）、SSH の Remote では **Start session**。次に **Copy machine…**。最後に **Delete machine…** または **Remove remote** です。その種類の Remote に適用できる操作だけが表示されます。SSH の Remote には起動・停止とコピーの操作がなく、Local には **Use as default** だけがあります。起動・停止の操作は状態に従います: 停止中は **Start**、サスペンド中は **Resume**、起動中は **Suspend…** と **Stop…**、エラー時は **Start** と **Stop…** です。状態の遷移中は、次に使える操作が完了まで薄く表示されます。適用できるが別の理由で使えない操作は薄く表示され、選択すると一覧の下に理由（例: **Template too old to copy**、**Sign in on the account tab first**、hangar に到達できないこと）が表示されます。タブを開いている間は一覧が自動で更新されるため、状態を確認する専用の操作はありません。

タブをクリックすると開き、Remote をクリックすると選択し、操作をクリックすると実行します。キーボードでは、他のタブと同じく ←/→（**h**/**l**、**Tab**/**Shift+Tab** も可）ですべての settings タブを切り替えます。remotes タブと images タブでは ↑/↓（または **k**/**j**）でフォーカス中のペイン内を移動し、**Enter** で一覧から操作へ移動して選択中の操作を実行し、**Esc** で一覧へ戻ります。一覧で **Esc** を押すと Settings を閉じます。最下行にこれらのキーが表示されます。フォームと確認（Remote の追加・編集、停止、サスペンド、削除、マシンのコピー、サインアウト）はダイアログとして開き、閉じると同じタブ・Remote・操作が選択された状態に戻ります。

**+ Add remote → Provider: SSH** で SSH 接続先を手動追加できます。表示名、SSH ターゲットまたはエイリアス、固定の Herdr session 名、必要に応じてリモートの既定ディレクトリを指定します。互換性のある Herdr と非対話 SSH 認証を、接続先にあらかじめ用意してください。**Test connection** は SSH と実行中の session を確認し、**Start session** はインストール済みの session を起動し、Remote を有効にします。ソフトウェアのインストールや置き換えは行いません。

Local または Remote を選び、**Use as default** で新規作成先を設定します。**New workspace**（キーバインド、サイドバーの **new workspace**、モバイルメニュー）は、作成先を尋ねずに既定のマシン（未設定なら Local）に、そのマシンの既定ディレクトリで workspace を作成します。ディレクトリが空欄なら接続先サーバーの既定値を使います。既定の作成先は現在表示しているマシンと独立しています。`prompt_new_workspace_name = true` の場合は、単一マシンのときと同じく先に名前を尋ねます。1 つの workspace 内の全 tab と pane は同じマシンで動作し、1 つのリモート session に複数の workspace を作成できます。

New workspace がマシンを起動することはありません。既定のマシンが停止中、接続中、無効、またはサイドバーで非表示の場合は、「Default machine box isn't connected — start it in Settings → remotes, or choose another default」のような通知を表示し、何も作成しません。別のマシンに workspace を作成するには、先にそのマシンで **Use as default** を選ぶか、`herdr --machine <label-or-id> workspace create` を実行してください。

表示中以外のマシンでは作成がバックグラウンドで実行され、そのマシンの一覧に現れた時点で新しい workspace にフォーカスします。その間にマシンを切り替えたりダイアログを開いたりした場合はフォーカスしません。タイムアウト時は結果が不明な場合があるため、再試行の前に接続先の workspace 一覧を確認してください。Herdr が作成要求を自動で再送することはありません。

### hangar マシン

Herdr はサインイン中の hangar アカウントのマシンを Settings の **remotes** タブに一覧表示します。1 台ずつ追加する必要はありません。サインインは `hangar` CLI と共有します（`~/.config/hangar/credentials.json`）。`hangar login` 済みならすぐにマシンが表示されます。未サインインの場合は Settings の **account** タブからサインインし、開いたブラウザーで完了してください。サーバーの既定値は `https://152.236.1.51` です。別のサーバーを使うには、Herdr 起動前に `HANGAR_SERVER` を設定してください。

**account** タブには、サインイン中のアカウント（ログイン名、例: **@octocat** は remotes、images、account タブの右上にも表示されます）と **Switch account…**（別のアカウントでのサインインも可能）、**Sign out…** が表示されます。未サインインまたはサインインの期限切れの場合は **Sign in** と **Sign up with invite code…** が表示されます。hangar の使用量と上限（保存データ量、マシン数、イメージ数。hangar が 1 時間ごとに集計）も表示されます。**Sign in** はブラウザーで hangar のサインインページを開きます。GitHub で承認すると、ブラウザーは Herdr が待機中に `127.0.0.1` で提供するページに戻るので、タブを閉じてかまいません。Herdr は最大 5 分待ち、**Esc** でキャンセルできます。SSH 経由（ディスプレイなしで `SSH_CONNECTION` または `SSH_TTY` が設定されている場合）、`DISPLAY` も `WAYLAND_DISPLAY` もない Linux、ブラウザーを開けない場合、またはサーバーがブラウザーサインインに対応していない場合は、代わりに GitHub のデバイス認証ページで入力するコードを表示します。**Sign out…** は確認後、サーバー側でサインインを取り消し、`~/.config/hangar/credentials.json` を削除します。そのため `hangar` CLI もサインアウトされます。マシンは動き続けますが、再びサインインするまで hangar の Remote の起動・停止・再接続はできません。

hangar は招待制です。hangar アカウントを作成するには、**account** タブで **Sign up with invite code…** を選び、受け取った招待コード（`hgi_` で始まります。前後の空白は無視されます）を入力して **Enter** を押します。Herdr は **Sign in** と同じサインイン（ブラウザーまたはデバイスコード）を招待コード付きで実行し、GitHub アカウントがそのまま hangar アカウントになります。**Esc** で **account** タブに戻り、待機中のサインアップはキャンセルされます。コードが無効な場合（期限切れ、取り消し済み、使用済み）は、修正できるようコードを残したままフォームが開いたままになります。**Sign in** で GitHub アカウントがまだ hangar にないと表示された場合は、**Sign up with invite code…** が選択されます。招待コードに対応していないサーバーでは、サインアップが利用できないかコードが受け付けられなかったと表示されます。招待コードは hangar サーバーに送信されるだけで、Herdr はログにも `~/.config/hangar/credentials.json` などにも保存しません。

この一覧の正は hangar サーバーです。他の場所（`hangar` CLI、ダッシュボード、別のコンピューター）で作成・削除したマシンは自動的に表示・消去されます。Herdr はバックグラウンドで 10 分ごと、Settings の **remotes** タブを開いたとき、および開いている間は 15 秒ごと、自身のマシン操作の後、そして hangar マシンへの接続に失敗した直後に一覧を更新します。起動中のマシンは自動的に接続し、停止中・サスペンド中のマシンは状態付きで表示されるだけで、起動されることはありません。サインアウト中やサーバーに到達できない場合は、最後に受け取った一覧を **signed out** または **offline** と表示したまま使い、更新に失敗したことを理由にマシンを追加・削除することはありません。ワークスペースのあるマシンがサーバー側で削除された場合、Herdr は接続を切り、「machine deleted on server」と表示し、再接続を試みません。

Herdr がマシンごとに保持するのはローカルの設定だけです。表示名（**Edit…**。hangar 側の名前は変わりません）、Herdr session、既定ディレクトリ、**Use as default**、**Hide from sidebar** です。非表示にしたマシンはサイドバーに表示されず接続もしませんが、Settings の **remotes** タブには残り、**Show in sidebar** で戻せます。hangar が一覧に含めなくなったマシンの設定は一緒に削除されます。

マシンを作成するには **Add remote → Provider: hangar** を選び、名前を入力して **Create and connect** を押します。新しいマシンは `herdr` テンプレートの既定サイズと永続ディスクで作成されます。Herdr はマシンの準備完了を待ち、一覧に追加して `herdr-remote` session を起動します。`herdr machine list` は一覧を更新してから hangar マシンを状態付きで表示します。`herdr machine add <name> --hangar` は追加するものがないため、マシンが一覧にあることを確認するだけです。

Herdr は hangar の SSH ゲートウェイ経由でマシンに接続します。専用の SSH 鍵と短期証明書（4 時間）を state ディレクトリの `client/hangar/ssh/` に保持し、ゲートウェイの設定は一時的な SSH 設定にだけ書き込みます。`~/.ssh/config` は変更しません。hangar マシンの SSH ターゲットは `hangar-<machine ID>` というエイリアスです。新しい接続の前に、マシンが起動中であることを確認し、証明書の残り時間が 15 分を切っていれば更新します。接続共有は有効のままです。マシン停止時にゲートウェイが既存接続を閉じるため、再接続で古い runtime への接続を再利用することはありません。

Herdr がマシンを暗黙に起動することはありません。マシンが停止中の場合、再接続、**Test connection**、`herdr --machine` は「use Start remote」というエラーになり、**New workspace** は何も作成せずに通知を表示します。remotes タブに各マシンの状態が表示されます。**Start** はマシンを起動し、準備完了を待ってから保存済みの Herdr session を起動します。**Stop…** はそのマシン上の**全 session とジョブ**を停止するため、確認を求めます。マシンが再接続しないようにし、その Herdr session の終了を試みてからマシンを停止します。永続ディスクのファイルは残りますが、実行中のプロセスは残りません。**Suspend…** は確認後、マシンが再接続しないようにし、マシンのメモリをスナップショットに保存します。Herdr session は中で動いたままなので、実行中のプログラムも保持されます。サスペンド中のマシンは **suspended** と表示され、**Start** は **Resume** になります。再開するとスナップショットを復元して再接続します。再接続や **Test connection** がマシンを再開することはありません。サインインの期限が切れると **Sign in to hangar** と表示されます。利用が許可されていないマシンでは「not allowed on this server」と表示され、再サインインは求めません。

同じローカル Herdr state ディレクトリを使うクライアント間では Remote 設定の変更を直列化し、マシン操作は hangar サーバーが直列化します。他のクライアントが接続先を変更した場合、ダイアログを開き直してください。SSH の Remote の **Remove remote** はローカルの接続設定だけを削除します。hangar マシンは Herdr だけから取り除くことはできないため、**Remove remote** はありません。**Delete machine…** はマシン名を示して確認を求め、確認後にマシンとそのディスク・スナップショットを完全に削除し、Herdr はその設定・証明書・接続キャッシュを破棄します。hangar 側でマシンがすでに削除済みならローカルの後片付けだけを行います。それ以外の失敗ではマシンは一覧に残るので、再試行できます。ターミナルでは `herdr machine remove <profile-id> --delete-machine` が同じ処理を行い、フラグがなければ削除と非表示の違いを説明して拒否します（`herdr machine disable <profile-id>` で hangar マシンを非表示に、`enable` で再表示し、`rename` で Herdr での表示名を設定します）。SSH catalog（`client/endpoints.json`）は generation-one 互換のまま SSH の Remote だけを保持します。hangar マシンの設定は `client/locations.json` に、最後に受け取ったマシン一覧は `client/hangar-machines.json` に保存します。以前の Herdr で保存した hangar の Remote はアップグレード時に変換され、エンドポイント ID（開いているワークスペースと session 状態が引き継がれます）、名前、session、既定ディレクトリを保持します。以前の Instacloud 連携で作成した Remote はアップグレード時に無効化されます。profile と既定ディレクトリは残るので、不要なら削除してください。

#### マシンのコピー

hangar の Remote で **Copy machine…** を選ぶと、クローンかイメージのどちらかを作成できます。2 つの選択肢を並べ、それぞれが何をコピーするかを表で示す選択画面が開きます:

|                     | Clone now   | Save as image  |
| ------------------- | ----------- | -------------- |
| Installed software  | ✓           | ✓              |
| System settings     | ✓           | ✓              |
| Repos & home files  | ✓           | ✗              |
| Logins (gh, claude) | ✓           | ✗              |
| Result              | new machine | reusable image |

←/→ または列のクリックで選び、**Enter**（またはもう一度クリック）でその選択肢のフォームに進みます。フォームで **Esc** を押すと選択画面に戻り、選択画面で **Esc** を押すと同じ Remote と操作が選択された remotes タブに戻ります。

どちらも停止中のマシンが必要です。起動中のマシンでは、フォームが **Stop machine and clone** または **Stop machine and save** を提示します。これは **Stop…** と同じ手順（再接続の防止、Herdr session の終了、マシンの停止）でマシンを停止してからコピーします。サスペンド中のマシンは一度再開してから停止します。コピー後もマシンは停止したままなので、作業を続けるには **Start** を使います。マシン ID のリセットに対応していない古いテンプレートから作成したマシンはコピーできません（**Template too old to copy**）。フォームにその旨が表示されるので、最新テンプレートで新しいマシンを作成・設定してからコピーしてください。

##### クローン

**Clone now** はこのマシンとまったく同じ 2 台目のマシンを作成します。ルートディスク**と** `/data` ディスクの両方をコピーします。新しいマシンの名前（英小文字・数字・`-`。既定は `<machine>-clone`）を入力して確定します。両ディスクの内容はすべてコピーされます。インストール済みソフトウェア、システム設定、リポジトリ、ホームディレクトリ（`/data/home`）、そこに保存されたログイン情報（gh、Claude、Codex、SSH 鍵など）も含まれるため、クローンは元のマシンと同様に扱ってください。クローンには独自の SSH ホスト鍵、マシン ID、ホスト名が割り当てられます。Herdr はクローンが起動して準備完了になるまで待ち、**Create new machine** と同様に remotes タブに追加して Herdr session を開始します。クローンは hangar のマシン数上限に数えられます。

##### イメージ

**Save as image** は新しいマシンの出発点として、マシンのルートディスクだけを保存します。名前（英小文字・数字・`-`）と任意の説明を入力して確定します。インストール済みソフトウェアとシステム設定は含まれますが、ホームディレクトリ（`/data/home`）のファイル、そこに保存されたログイン情報（gh、Claude、Codex、git、SSH）、`/data/workspace` のリポジトリは含まれません。`sudo gh auth` の認証情報や `/etc/environment` のトークンなど、ルートディスクに書き込まれたものはすべて含まれるため、保存前に削除してください。イメージは自分の hangar アカウントだけが使えます。

**images** タブは自分のイメージを新しい順に作成日付きで一覧表示します。選択すると説明、作成日、保存元のマシン、テンプレート、サイズが表示され、**New machine from image…**（そのイメージを **Source** に選んだ状態で **Add remote** を開きます）または **Delete image…** を選べます。イメージがまだない場合は、**Copy machine… → Save as image** で保存する方法がタブに表示されます。

**+ Add remote → Create new machine** を選び、**Source** でイメージを選ぶこともできます。一覧には各イメージの名前、作成日、保存元のマシンが表示されます。既定のソースは最新の `herdr` テンプレートです。イメージから作成したマシンはイメージのルートディスクと新しい空の `/data` を持つため、ツールへのログインはやり直してください。イメージをソースとして選んでいるときは **Delete image…** で確認後に削除できます。そのイメージから作成済みのマシンには影響しません。

## 接続前の確認

リモートマシンへの通常の SSH アクセスが必要です。最初に確認してください:

```bash
ssh workbox
```

`workbox` は SSH config のホスト名です。`ssh://you@server:2222` のような接続先も使えます。

複数マシンへの接続は Linux、macOS、Windows のクライアントに対応し、x86_64 または aarch64 の Linux と macOS サーバー、および x86_64 の Windows サーバーに接続できます。対話型セットアップでは確認後に完全なリモートパッケージをインストールまたは更新できます。バックグラウンド再接続ではインストール済みのパッケージだけを探します。SSH 設定、認証、カスタムバイナリについては [SSH 越しのリモートアタッチ](/ja/docs/persistence-remote/)を参照してください。

## マシンを追加する

インストールや置き換えの前に確認できるよう、対話型ターミナルで実行します:

```bash
herdr machine add workbox
```

対話型ターミナルでは、Herdr は実行中のセッションを検出します。1 つだけならそれを選択し、複数ある場合は Up/Down と Enter で選べます。Esc または Ctrl+C でキャンセルします。問い合わせに成功しても実行中のセッションがなければ、セットアップは `default` を使います。Herdr がインストールされていない場合は、`default` 用にインストールするか確認します。インストール済みバイナリがセッションを報告できない場合はエラーを表示します。セッションを明示的に選ぶには `--remote-session <name>` を指定してください。

デフォルトセッションはサイドバーに `workbox` と表示されます。これは `user@` プレフィックスを除いた SSH ホストです。別の名前にするには `--label "Build machine"` を追加します。1 つのプロファイルは 1 つのリモートセッションを対象とし、そのホストの全セッションをまとめるものではありません。非対話型コマンドでは、`--remote-session` がない限り `default` を使います。

検出を省略して特定のセッションを使うには、`--remote-session` を追加します:

```bash
herdr machine add workbox --remote-session agents
```

`--label` がない場合、このマシンは `workbox/agents` と表示されます。デフォルト名がすでに使われている場合、`machine add` は `--label` の指定を求めます。

Windows サーバーでは、SSH ユーザーが所有する Herdr プロセスで使われている実行ファイルも確認します。再利用前に機能を検証するため、SSH の `PATH` が古いインストールを指していても、互換性のある実行中ビルドを利用できます。

Herdr はインストール済みバイナリと実行中サーバーをそれぞれ確認し、対象のバックグラウンドサーバーを起動してからプロファイルを保存します。互換性があればクライアントとサーバーのバージョンは一致しなくても構いません。未インストールや非互換の場合は、承認付きのセットアップを行います。実行中サーバーの置き換えが必要なら、サーバーとペインのプロセスを停止する前に確認し、その後に互換サーバーを起動します。デフォルトの回答は No です。インストールと置き換えの両方が必要な場合は、1 回の確認で承認します。`machine add` は実験的なライブハンドオフを使いません。セットアップをキャンセルした場合や失敗した場合、プロファイルは保存されません。

`herdr` で UI を開きます。ローカルクライアントがすでに開いていれば、追加や有効化したマシンは通常 1 秒以内に表示され、選択を変えずにバックグラウンドで接続します。マシン切り替え中の変更は、切り替えの完了後に反映します。セットアップ終了後もリモートサーバーは動き続けます。

## マシンを切り替える

サイドバーでマシンまたはそのワークスペースを選びます。選択中のマシンだけがペイン入力とターミナルサイズを受け取り、表示するターミナル内容とグラフィックスを送信します。ほかの接続済みマシンは、ペイン画面を送らずにワークスペース情報、エージェント状態、通知を更新し続けます。

各マシンの横の矢印をクリックすると、現在のワークスペースを切り替えずに一覧を折りたためます。再接続中のマシンでも操作できます。

キーボードでは `prefix+w` を押し、ワークスペース移動キー（デフォルトは Up/Down）で接続済みマシンのワークスペースをサイドバー順に選びます。Enter で移動を確定し、Esc またはプレフィックスキーで切り替えずにキャンセルします。縮小・展開サイドバーとも、折りたたまれたマシン内の選択行を表示します。デスクトップでは両端で折り返し、モバイルの切り替え画面では先頭と末尾で止まります。切断中のマシンは飛ばします。

別マシンのワークスペースをハイライトしたら、他のキー操作の前に Enter で切り替えてください。現在のマシンでペイン、タブ、ワークスペース、カスタムコマンドの操作が誤って実行されるのを防ぎます。クリックすると、デスクトップでのリモート移動のプレビューはキャンセルされます。展開サイドバーはマシンごとの worktree グループの折りたたみ状態を反映します。

起動時は SSH 接続を待たずに Local を開きます。Local を選ぶと、リモートの応答を待たずに未完了の切り替えをキャンセルします。Local 自体が再接続中なら、準備ができた時点で選択を再開します。Local の新しい画面とターミナル設定が届くと入力できます。応答しないマシンがほかのマシンの入力を妨げることはありません。同じサーバーに接続した複数のクライアントは、それぞれ別のタブを表示できます。同じタブを表示した場合のサイズについては[クライアントとサーバー](/ja/docs/concepts/)を参照してください。

接続が切れると、最後のワークスペースとエージェント状態を暗く表示します。これはキャッシュであり、現在の状態ではありません。新しい接続と対応する画面が届くまで、そのペインへの入力や移動は無効です。再接続しても、使用中のマシンから選択を奪いません。

## 名前の変更、無効化、削除

ラベルやホスト名から推測せず、一覧からプロファイル ID を取得します:

```bash
herdr machine list
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id> [--delete-machine]
```

スクリプトでは `machine list` に `--json` を追加できます。

名前の変更は表示ラベルだけを更新し、再接続しません。無効化はプロファイルを残し、削除はプロファイルを忘れます。どちらもクライアントからそのマシンだけを切断し、到達不能なホストでも操作できます。リモートセッションとエージェントは動き続けます。

表示中のマシンを削除または無効化すると Local に戻ります。Local が利用できない場合は、別のリモートを選ばず、その状態を表示して再接続します。有効な保存済みマシンがあれば、Local が失敗または再起動してもクライアントを使い続けられます。

## 接続の問題

- **Reconnecting:** ネットワーク中断、スリープ、SSH 障害の後は自動で再試行します。失敗が続くと待機間隔は最大 2 分まで延び、短時間だけ接続に成功してもリセットされません。1 分間安定して接続できると、次の中断では再び短い間隔で再試行します。SSH 接続はアプリケーションの通信を監視し、通信がない間はヘルスチェックを行うため、切れた接続が Online のままになりません。Local はリモート用のプローブではなく、ネイティブ接続の終了や失敗を検知します。
- **Attention:** 認証、ホスト鍵の承認、互換サーバーの準備などが必要です。ほかのマシンは利用できます。**`! auth`** は認証失敗、**`! error`** は別の問題を示します。バッジをクリックするとエラーと CLI コマンドを表示します。折りたたみ時はどちらも `!` です。
- **保存済みマシンのファイルエラー:** カタログを読み取れない、または内容が不正な場合、現在の接続は変更しません。通知を表示して自動で読み取りを再試行します。

サイドバーでは、リモートマシンの名前の前に `⇄` が付きます。Local には付きません。接続中のマシンにはそれ以外何も表示しません。それ以外の場合、マシン行には **connecting…** または **reconnecting…**（黄）、**disabled**（薄色。停止中・サスペンド中・非表示の hangar マシンも含む）、または **`! error`** / **`! auth`** が表示されます。折りたたみ時は接続中・再接続中が `…` になります。マシンの状態にはドットや円を使いません。これらは Agent の状態を表すためのものです。

両端のインストールがブリッジのアイドル終了に対応している場合、Linux と macOS への保存済みマシン接続は、どちらの方向にも通信がない状態が 1 分続くとリモートブリッジを終了します。スリープ時間も含み、復帰時に期限を確認します。正常なアイドル接続ではヘルスチェックを交換するため、継続的な出力を見るためにキーを入力する必要はありません。ブリッジ終了後もリモートサーバー、セッション、ペインのプロセスは動き続けます。古いインストールとは、この追加機能なしで接続できます。

バックグラウンド接続がプロンプトに回答したり、サーバーのインストール、更新、再起動、ハンドオフを行ったりすることはありません。認証以外の Attention の場合は、Herdr が表示する単独接続用のコマンドを対話型ターミナルで実行してください。例:

```bash
herdr --remote workbox
```

プロファイルの接続先を使います。名前付きセッションを選んだ場合だけ `--session <name>` も指定します。セットアップ後、開いているクライアントは自動的に再試行します。`machine reconnect` は Herdr をインストール・更新しません。バージョンが違うという理由だけで実行中サーバーを止めないでください。

認証に失敗したら、まず通常の SSH を確認します。パスフレーズ付きの鍵は、非対話型のバックグラウンド接続を始める前に `ssh-add` で読み込んでください。

リモートペイン内で Git 認証や SSH 署名を使うには、信頼できるホストについて SSH 設定で `ForwardAgent yes` を有効にしてください。Herdr が転送を有効にすることはありません。セッションがエージェント付きで起動した場合、更新済みの Linux と macOS サーバーはペインに安定したエージェントアドレスを与えるため、`--remote` または保存済みマシンが再接続した後も、既存ペインと新規ペインの両方で転送されたエージェントを利用できます。動作中の継承エージェントや先行接続は、後から接続したクライアントや一時的なセットアップ確認より優先されます。それが消えた場合は、別の稼働中アタッチがエージェントを提供できます。

これにはローカルクライアントだけでなく、更新済みのリモートサーバーが必要です。エージェントなしで開始したローカルセッションでは `SSH_AUTH_SOCK` を変更しません。サーバー更新前、またはセッションに初めてエージェントが提供される前に作成されたペインは元の環境を維持するため、安定したアドレスを継承するには一度作り直す必要があります。互換性のある古いサーバーやエージェント転送なしの接続も、通常どおりアタッチできます。

## 設定と自動化

UI はデフォルトでクライアントのローカルテーマ、サイドバー設定、キーバインドを使います。選択中サーバーが公開するカスタムコマンドとプラグインは、そのサーバーで実行します。Herdr はローカルのプラグイン、設定、実行ファイル、シークレットを SSH ホストにコピーしません。リモートにコマンドがなければエラーを表示します。クライアント設定を編集したら UI の `reload config` を使います。[設定](/ja/docs/configuration/)を参照してください。

複数のマシンがある場合、デフォルトの Agent 行に `machine` トークンを表示します。既存のカスタム行は維持されるため、ラベルが必要なら `machine` を追加してください。[サイドバーの行レイアウト](/ja/docs/configuration/)ではマシンラベルの条件付き色も設定できます。

ワークスペース、タブ、ペインの ID とエージェント名はサーバーごとに独立しています。2 台に同じ `w1:p1` や `reviewer` が存在する場合があります。UI でマシンを選んでも、既存ペイン内の CLI は継承したセッションとソケットを使い続けます。リモート自動化では `herdr --machine <label-or-id> agent list` で ID を取得し、操作時にも同じプレフィックスを指定します。CLI は保存済みプロファイルの SSH 接続先とセッションを直接使うため、TUI を開く必要はありません。`--machine` を省略した場合の動作は変わりません。対応コマンド、更新要件、パスの扱いは [CLI リファレンス](/ja/docs/cli-reference/#保存済み-ssh-マシン) を参照してください。

## 更新と保存データ

保存するのは、不透明な ID、ラベル、SSH 接続先、明示的なリモートセッション名、有効状態だけです。パスワード、秘密鍵、エージェントのチケット、SSH 制御ソケットはカタログに保存しません。認証は OpenSSH が扱います。

Herdr は、`--machine` コマンドを繰り返し実行するときに検出を省略できるよう、各マシンのリモート OS と解決済み実行ファイルパスを別途記憶します。既存のプロファイルでは、初回使用時に不足情報を学習します。このキャッシュは任意です。キャッシュファイルがない、不正、または書き込み不能でもコマンドの動作は妨げられません。コマンドは引き続き実行中サーバーの互換性を確認します。キャッシュした実行ファイルがない、または API 転送に対応しなくなった場合、最初の読み取り専用確認中に再検出します。リモートの状態をすでに変更した可能性があるコマンドを自動的に再実行することはありません。

クライアントとサーバーは同一バージョンを要求せず、互換性を合意します。保存済みマシンへの接続には、サーバーの `surface_interest` と `health_check` 能力も必要です。未対応の古いサーバーは、単独接続できても明示的に更新するまで Attention になります。そのほかの未対応メソッドは、該当する操作だけを無効にします。

互換クライアントを更新しても、リモートサーバーを置き換えたりエージェントを停止したりしません。新しいサーバー機能が必要なら、そのサーバーを明示的に更新します。通常の置き換えでは、サーバーとペインのプロセスを停止する前に確認します。

ライブハンドオフは実験的なオプトイン機能です。単独接続のセットアップで対応サーバーを置き換える場合、`herdr --remote` に `--handoff` を明示的に追加できます。通常の接続や認証の修復には不要です。[更新](/ja/docs/install/)と[セッション状態と復元](/ja/docs/session-state/)で、それぞれの操作が何を維持するか確認してください。
