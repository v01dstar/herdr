title: 连接机器
description: 在一个 Herdr 窗口中使用 Local 和已保存的 SSH 机器，集中查看智能体，各连接独立重连。
---

将本地工作和远程智能体放在同一个 Herdr 窗口中。SSH 机器只需保存一次，就能在它的工作区与 Local 之间切换，无需再开一个客户端。智能体列表汇总已连接的机器，让你看到工作在哪里运行，以及谁在等待回答。

每台机器保留自己的 Herdr 服务器、会话和进程。一台机器断线不会影响其他连接。

Herdr 会请求 SSH 压缩，以减少受限连接上的屏幕更新流量。这适用于较旧的兼容 Herdr 服务器，也不会改变按键或其他输入的传送方式。Herdr 的 `-C` 选项会覆盖 SSH 配置中的 `Compression no`。如果 SSH 通过外部 ControlMaster 复用现有连接，该连接会保留原来的压缩设置。

### 恢复 SSH 认证

在 Linux 和 macOS 上，启用 `remote.manage_ssh_config=true` 后，添加机器、侧边栏和 API 操作共享已批准的 OpenSSH 连接。运行 `herdr machine status [<label-or-id>] [--json]` 可进行新的非交互式检查。**reachable** 表示远程 Herdr 当前可用，不代表每个 TUI 都已连接。在终端运行 `herdr machine reconnect <label-or-id>` 完成原生 SSH 认证并验证已保存的机器；该命令不会安装或更新 Herdr。已打开的客户端会在 30 秒内重试，无需重启。点击 **`! auth`**、**`! error`** 或失败后的重连状态，会显示包含最新错误及 CLI 命令的通知，不会打开认证弹窗。机器行其余部分仍用于展开或折叠。

共享连接使用 `ControlPersist 600`，表示空闲 10 分钟，并不表示 MFA 有效期。活动连接可以继续保持，但企业策略、SSH 服务器或网络可能更早终止连接。Windows 本地恢复尚未支持。未受管理的 SSH 连接由你负责认证；单独运行 `ssh` 不会授予 Herdr 批准，除非它使用共享 ControlPath。主机密钥检查不会放宽；未知或已更改的主机密钥仍显示为 **Attention**。

## 在 Settings 中配置 Remote

Remote 在 Settings 中排在其他设置之后的三个标签页中配置：**remotes**、**images** 和 **account**（完整的标签行为 `theme  indicators  sound  toasts  integrations  remotes  images  account`）。右上角显示当前登录的 hangar 用户。终端较窄时标签行会滚动，始终显示当前打开的标签页，并用 `‹` 和 `›` 标出被隐藏的标签页。Remote 弹窗比其他标签页高几行，以便放下机器的全部操作。

**remotes** 标签页依次列出 Local、hangar 机器和 SSH Remote，最后是 **+ Add remote**。Remote 的名称前带有 `⇄`（Local 没有），右侧以文字显示状态：**running**（绿色），**stopped** 或 **suspended**（暗色），**starting…**、**stopping…** 等过渡状态（黄色），**error**（红色），**unknown**，SSH Remote 则显示 **connected**、**disabled** 或 **offline**。无法访问 hangar 或未登录时，状态显示为 **offline** 或 **signed out**，表示最后一次同步的状态。**default**、**hidden** 等标注显示在状态之前。右侧窗格以 `name · hangar|ssh · state` 的形式显示选中的 Remote，下方显示 hangar 报告的模板、规格，以及克隆来源机器或创建所用镜像（处于错误状态的机器还会显示最后一次错误）。再往下是单列操作，各组之间以空行分隔：**Start** 或 **Resume**、**Suspend…**、**Stop…**；然后是 **Test connection**、**Edit…**、**Use as default**、**Hide from sidebar**（或 **Show in sidebar**），SSH Remote 还有 **Start session**；然后是 **Copy machine…**；最后是 **Delete machine…** 或 **Remove remote**。只显示适用于该类 Remote 的操作：SSH Remote 没有启停和复制操作，Local 只提供 **Use as default**。启停操作随状态变化：已停止时为 **Start**，已挂起时为 **Resume**，运行中为 **Suspend…** 和 **Stop…**，出错时为 **Start** 和 **Stop…**。处于过渡状态时，下一步可用的操作会变暗显示，直到过渡完成。适用但因其他原因暂不可用的操作会变暗，选中后在列表下方说明原因，例如 **Template too old to copy**、**Sign in on the account tab first** 或无法访问 hangar。标签页打开期间列表会自动刷新，因此没有单独的状态操作。

点击标签页即可打开，点击 Remote 即可选中，点击操作即可执行。使用键盘时，与其他标签页一样，←/→（也可用 **h**/**l**、**Tab**/**Shift+Tab**）在所有 settings 标签页之间切换。在 remotes 和 images 标签页中，↑/↓（或 **k**/**j**）在当前焦点窗格内移动，**Enter** 从列表进入操作并执行选中的操作，**Esc** 返回列表；在列表中按 **Esc** 关闭 Settings。底部一行会显示这些按键。表单和确认（添加或编辑 Remote、停止、挂起、删除、复制机器、退出登录）以弹窗打开，关闭后会回到原来的标签页，并保持之前选中的 Remote 和操作。

选择 **+ Add remote → Provider: SSH** 手动添加 SSH 位置，填写显示名称、SSH 地址或别名、固定的 Herdr session 名称，以及远端默认目录。远端应已安装兼容版本的 Herdr，并配置好无需交互的 SSH 认证。**Test connection** 检查 SSH 和运行中的 Herdr session；**Start session** 启动已安装的 session 并启用该 Remote，不安装或替换远端软件。

选中 Local 或某个 Remote，点击 **Use as default**。**New workspace**（快捷键、侧边栏的 **new workspace** 或移动端菜单）不再询问位置，而是直接在默认机器（未设置时为 Local）上、以该机器的默认目录创建 workspace；目录留空时由目标服务器选择。默认位置独立于当前显示的机器。设置 `prompt_new_workspace_name = true` 时，会像单机时一样先询问名称。一个 workspace 的所有 tab 和 pane 都在同一台机器运行，一个远端 session 可以包含多个 workspace。

New workspace 不会启动机器。默认机器已停止、正在连接、已禁用或已从侧边栏隐藏时，Herdr 会显示类似“Default machine box isn't connected — start it in Settings → remotes, or choose another default”的提示，并且不创建任何内容。要在其他机器上创建 workspace，请先对该机器选择 **Use as default**，或运行 `herdr --machine <label-or-id> workspace create`。

在当前显示之外的机器上，创建在后台执行，新 workspace 出现在该机器的列表中后会自动获得焦点；如果期间切换了机器或打开了弹窗，则不会抢占焦点。超时可能意味着结果未知，应先检查目标机器的 workspace 列表再重试。Herdr 不会自动重复发送创建请求。

### hangar 机器

Herdr 会在 Settings 的 **remotes** 标签页中列出当前登录的 hangar 账号下的所有机器，无需逐台添加。Herdr 与 `hangar` CLI 共享登录信息（`~/.config/hangar/credentials.json`）：如果已运行过 `hangar login`，机器会立即出现；否则请在 Settings 的 **account** 标签页中登录，并在打开的浏览器中完成。服务器默认为 `https://152.236.1.51`；如需使用其他服务器，请在启动 Herdr 前设置 `HANGAR_SERVER`。

**account** 标签页显示当前登录的账号（登录名，例如 **@octocat**，也显示在 remotes、images 和 account 标签页的右上角），并提供 **Switch account…**（重新登录，可换用其他账号）和 **Sign out…**；未登录或登录已过期时提供 **Sign in** 和 **Sign up with invite code…**。它还显示 hangar 的用量和上限：已存储的数据量、机器数和镜像数（由 hangar 每小时统计一次）。**Sign in** 会在浏览器中打开 hangar 的登录页面；在 GitHub 上批准后，浏览器会回到 Herdr 等待期间在 `127.0.0.1` 上提供的页面，之后可以关闭该标签页。Herdr 最多等待 5 分钟，按 **Esc** 可取消。通过 SSH 使用时（设置了 `SSH_CONNECTION` 或 `SSH_TTY` 且没有显示环境）、在没有 `DISPLAY` 和 `WAYLAND_DISPLAY` 的 Linux 上、无法打开浏览器时，或服务器不支持浏览器登录时，Herdr 会改为显示一个验证码，需在 GitHub 设备登录页面输入。**Sign out…** 确认后会在服务器上撤销登录，并删除 `~/.config/hangar/credentials.json`，因此 `hangar` CLI 也会一并退出登录。机器会继续运行，但在重新登录之前，hangar Remote 无法启动、停止或重连。

hangar 采用邀请制。要创建 hangar 账号，请在 **account** 标签页中选择 **Sign up with invite code…**，输入收到的邀请码（以 `hgi_` 开头，前后空格会被忽略），然后按 **Enter**。Herdr 会带着邀请码执行与 **Sign in** 相同的登录流程（浏览器或设备验证码），你的 GitHub 账号即成为 hangar 账号。按 **Esc** 返回 **account** 标签页，并取消正在等待的注册。如果邀请码无效（已过期、已撤销或已被使用），表单会保持打开并保留邀请码，方便修改。如果 **Sign in** 提示你的 GitHub 账号尚未加入 hangar，会自动选中 **Sign up with invite code…**。不支持邀请码的服务器会提示注册不可用或邀请码未被接受。邀请码只会发送给 hangar 服务器：Herdr 不会将其写入日志，也不会保存到 `~/.config/hangar/credentials.json` 或其他任何地方。

该列表以 hangar 服务器为准。在其他地方（`hangar` CLI、控制台、其他电脑）创建或删除的机器会自动出现或消失：Herdr 在后台每 10 分钟刷新一次，打开 Settings 的 **remotes** 标签页时立即刷新、打开期间每 15 秒刷新一次，在自身的机器操作完成后刷新，并在连接 hangar 机器失败时立即刷新。运行中的机器会自动连接；已停止或已挂起的机器会显示其状态，但绝不会被启动。未登录或无法访问服务器时，Herdr 继续显示最后一次获取的列表，并标记为 **signed out** 或 **offline**，绝不会因刷新失败而添加或移除机器。如果你有工作区的机器在服务器上被删除，Herdr 会断开连接，显示“machine deleted on server”，且不会尝试重连。

Herdr 只为每台机器保存本地偏好：显示名称（**Edit…**；hangar 中的名称不变）、Herdr session、默认目录、**Use as default** 和 **Hide from sidebar**。隐藏的机器不会显示在侧边栏，也不会连接，但仍列在 Settings 的 **remotes** 标签页中，可用 **Show in sidebar** 恢复。hangar 不再列出的机器，其偏好会一并删除。

要创建机器，选择 **Add remote → Provider: hangar**，输入名称并点击 **Create and connect**。新机器使用 `herdr` 模板的默认规格和持久磁盘。Herdr 会等待机器就绪，将其加入列表并启动 `herdr-remote` session。`herdr machine list` 会先刷新列表，再显示 hangar 机器及其状态；`herdr machine add <name> --hangar` 无需添加任何内容，只会确认该机器已在列表中。

Herdr 通过 hangar SSH 网关连接机器。它在 state 目录的 `client/hangar/ssh/` 中保存自己的 SSH 密钥和短期证书（4 小时），网关设置只写入临时 SSH 配置，不会修改 `~/.ssh/config`。hangar 机器的 SSH 目标是别名 `hangar-<machine ID>`。每次建立新连接前，Herdr 会确认机器正在运行，并在证书剩余时间不足 15 分钟时续期。连接复用保持开启：机器停止时网关会关闭现有连接，因此重连不会复用指向旧 runtime 的连接。

Herdr 不会隐式启动机器。机器停止时，重连、**Test connection** 和 `herdr --machine` 会提示“use Start remote”，**New workspace** 则显示提示且不创建任何内容。remotes 标签页会显示每台机器的状态。**Start** 启动机器，等待就绪后启动已保存的 Herdr session。**Stop…** 需要确认，因为它会停止该机器上的**全部 session 和任务**：先阻止该机器重连，尝试关闭其 Herdr session，再停止机器。持久磁盘上的文件保留，运行中的进程不会保留。**Suspend…** 确认后会阻止该机器重连，并把机器内存保存为快照；其中的 Herdr session 保持运行，运行中的程序也会保留。挂起的机器显示为 **suspended**，**Start** 变为 **Resume**；恢复时会还原快照并重连。重连和 **Test connection** 永远不会恢复机器。登录过期时显示 **Sign in to hangar**；无权使用的机器显示“not allowed on this server”，不会要求重新登录。

共享本地 Herdr state 目录的客户端会串行修改 Remote 设置，机器操作由 hangar 服务器串行执行。其他客户端修改连接目标后，需要重新打开弹窗才可操作新目标。SSH Remote 上的 **Remove remote** 只删除本地连接设置。hangar 机器无法仅从 Herdr 中移除，因此没有 **Remove remote**：**Delete machine…** 会先确认并列出机器名，确认后永久删除机器及其磁盘和快照，Herdr 随即清除其偏好、证书和连接缓存。如果 hangar 中机器已被删除，Herdr 只做本地清理；其他失败会让机器保留在列表中，便于重试。在终端中，`herdr machine remove <profile-id> --delete-machine` 执行相同操作；不带该参数时会拒绝，并说明删除与隐藏的区别（`herdr machine disable <profile-id>` 隐藏 hangar 机器，`enable` 重新显示，`rename` 设置 Herdr 中的显示名称）。SSH catalog（`client/endpoints.json`）保持 generation-one 兼容，只保存 SSH Remote；hangar 机器的偏好保存在 `client/locations.json`，最后一次获取的机器列表保存在 `client/hangar-machines.json`。旧版 Herdr 保存的 hangar Remote 会在升级时转换，并保留其端点 ID（因此打开的工作区和 session 状态得以保留）、名称、session 和默认目录。之前通过 Instacloud 集成创建的 Remote 会在升级时被禁用，其 profile 和默认目录会保留，可自行删除。

#### 复制机器

在 hangar Remote 上选择 **Copy machine…**，可以创建克隆或镜像。它会打开一个选择界面，并排显示两个选项，并用表格说明各自复制的内容：

|                     | Clone now   | Save as image  |
| ------------------- | ----------- | -------------- |
| Installed software  | ✓           | ✓              |
| System settings     | ✓           | ✓              |
| Repos & home files  | ✓           | ✗              |
| Logins (gh, claude) | ✓           | ✗              |
| Result              | new machine | reusable image |

用 ←/→ 或点击某一列进行选择，按 **Enter**（或再次点击）进入该选项的表单。在表单中按 **Esc** 返回选择界面；在选择界面中按 **Esc** 返回 remotes 标签页，并保持之前选中的 Remote 和操作。

两者都需要已停止的机器。对于运行中的机器，表单会提供 **Stop machine and clone** 或 **Stop machine and save**：它按 **Stop…** 的相同步骤停止机器（阻止重连、关闭 Herdr session、停止机器），然后进行复制；已挂起的机器会先恢复再停止。复制后机器保持停止状态，如需继续使用请点击 **Start**。由不支持重置机器身份的旧模板创建的机器无法复制（**Template too old to copy**），表单会说明这一点；请用最新模板创建新机器，配置好后再复制。

##### 克隆

**Clone now** 会创建一台与当前机器完全相同的第二台机器：同时复制根磁盘**和** `/data` 磁盘。输入新机器的名称（小写字母、数字和 `-`，默认为 `<machine>-clone`）后确认。两块磁盘上的所有内容都会被复制：已安装的软件、系统设置、仓库、主目录（`/data/home`）以及保存在其中的登录信息（如 gh、Claude、Codex 和 SSH 密钥），因此请像对待原机器一样对待克隆机器。克隆机器拥有自己的 SSH 主机密钥、机器 ID 和主机名。Herdr 会等待克隆机器运行并就绪，然后像 **Create new machine** 一样将其加入 remotes 标签页并启动 Herdr session。克隆机器计入 hangar 的机器数量上限。

##### 镜像

**Save as image** 为新机器保存一个起点：只保存机器的根磁盘。输入名称（小写字母、数字和 `-`）和可选描述后确认。已安装的软件和系统设置会包含在内，但主目录（`/data/home`）中的文件、保存在其中的登录信息（gh、Claude、Codex、git、SSH）以及 `/data/workspace` 中的仓库不会包含。写入根磁盘的任何内容都会包含在内，例如 `sudo gh auth` 的凭据或 `/etc/environment` 中的令牌，请在保存前删除。镜像仅对你的 hangar 账号可见。

**images** 标签页按从新到旧列出你的镜像及其创建日期。选中一个镜像可查看描述、创建日期、来源机器、模板和大小，并可选择 **New machine from image…**（打开 **Add remote** 并把该镜像选为 **Source**）或 **Delete image…**。还没有镜像时，标签页会说明如何通过 **Copy machine… → Save as image** 保存镜像。

也可以选择 **+ Add remote → Create new machine**，并在 **Source** 中选择镜像；列表显示每个镜像的名称、创建日期和来源机器。默认来源是最新的 `herdr` 模板。基于镜像创建的机器使用镜像的根磁盘和一个新的空 `/data`，因此需要在新机器上重新登录各工具。将镜像选为来源时，可通过 **Delete image…** 在确认后删除它；已基于该镜像创建的机器不受影响。

## 连接前的准备

你需要能够通过普通 SSH 访问远程机器。先验证：

```bash
ssh workbox
```

`workbox` 可以是 SSH 配置中的主机名，也可以使用 `ssh://you@server:2222` 这样的目标。

多机器连接支持 Linux、macOS 和 Windows 客户端，连接目标可以是 x86_64 或 aarch64 的 Linux/macOS 服务器，也可以是 x86_64 的 Windows 服务器。交互式设置可在确认后安装或更新完整的远程软件包；后台重连只查找已安装的软件包。有关 SSH 配置、认证和自定义二进制文件，请参阅[通过 SSH 远程连接](/zh-cn/docs/persistence-remote/)。

## 添加机器

请在交互式终端中运行，以便 Herdr 在安装或替换内容之前询问：

```bash
herdr machine add workbox
```

在交互式终端中，Herdr 会发现运行中的会话：只有一个会话运行时自动选择；有多个时，可用 Up/Down 选择并按 Enter 确认。按 Esc 或 Ctrl+C 取消。查询成功但没有运行中的会话时，设置使用 `default`。未找到 Herdr 安装时，设置会提议为 `default` 安装。如果已安装的二进制文件无法报告会话，设置会报告错误；可传入 `--remote-session <name>` 明确选择会话。

默认会话在侧边栏中显示为 `workbox`，即去掉所有 `user@` 前缀的 SSH 主机名。添加 `--label "Build machine"` 可选择其他名称。一个机器配置只对应一个远程会话，不会汇总该主机的所有会话。非交互式命令使用 `default`，除非提供 `--remote-session`。

要跳过发现并使用指定会话，请添加 `--remote-session`：

```bash
herdr machine add workbox --remote-session agents
```

未提供 `--label` 时，这台机器显示为 `workbox/agents`。如果默认名称已被占用，`machine add` 会要求你传入 `--label`。

在 Windows 服务器上，设置还会检查 SSH 用户拥有的 Herdr 进程所使用的可执行文件。它会先验证其能力再复用，因此即使 SSH 的 `PATH` 指向较旧的安装，也能使用兼容的运行中构建。

Herdr 分别检查已安装的二进制文件和运行中的服务器，并在保存配置之前启动目标后台服务器。客户端和服务器版本只要兼容，就不必一致。未安装或不兼容时会进入需要批准的设置流程。如果必须替换运行中的服务器，会先询问是否停止它及其窗格进程，再启动兼容的服务器。默认回答为 No；同时需要安装和替换时，一次确认涵盖两项操作。`machine add` 不使用实验性的实时交接。取消或设置失败时，不会保存配置。

运行 `herdr` 打开 UI。如果本地客户端已经打开，新增或启用的机器通常会在一秒内出现并在后台连接，不改变当前选择。切换机器期间的配置变化会在切换完成后应用。设置结束后，远程服务器仍会运行。

## 切换机器

在侧边栏选择机器或其工作区。只有选中的机器接收窗格输入和终端尺寸，并提供可见的终端内容和图形。其他已连接机器仍会更新工作区信息、智能体状态和通知，但不传输窗格画面。

点击任意机器旁的箭头，可以折叠或展开其工作区列表，而不切换当前工作区。机器正在重连时也可以操作。

键盘导航先按 `prefix+w`，再使用工作区导航键（默认为 Up/Down），按侧边栏顺序高亮已连接机器上的工作区。Enter 确认切换；Esc 或前缀键取消，不切换机器。紧凑和展开的侧边栏都会显示高亮行，包括折叠机器内的行。桌面导航在两端循环，移动端切换器在首尾停止。已断开的机器会被跳过。

高亮其他机器的工作区后，请先按 Enter 再使用其他键盘操作，避免误对当前机器执行窗格、标签页、工作区或自定义命令。点击会取消桌面上的远程键盘导航预览。展开的侧边栏会保留每台机器的 worktree 分组折叠状态。

启动时会立即打开 Local，不等待 SSH 连接。选择 Local 也会立即取消尚未完成的远程切换，无需等待远程响应。如果 Local 自身正在重连，会在就绪后继续选中它。收到 Local 的新画面和终端设置后即可输入。一台机器无响应不会阻塞其他机器的输入。多个 Herdr 客户端也可以独立查看同一服务器上的不同标签页；共享标签页的尺寸规则见[客户端与服务器](/zh-cn/docs/concepts/)。

断线后，最后的工作区和智能体状态仍然可见，但会变暗。这是缓存，不是实时状态。在新连接和对应画面到达前，不能输入或导航到这些缓存窗格。重连不会从正在使用的机器抢走选择。

## 重命名、禁用或移除

从列表读取配置 ID，不要根据标签或主机名推测：

```bash
herdr machine list
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id> [--delete-machine]
```

用于脚本时，可给 `machine list` 添加 `--json`。

重命名只修改显示标签，不会重连。禁用会保留配置供以后使用，移除则会忘记该配置。两者都只从客户端断开该机器，即使主机无法访问也可以操作；远程会话和智能体仍会运行。

移除或禁用正在查看的机器会返回 Local。如果 Local 不可用，Herdr 会显示该状态并重试连接，而不是选择其他远程机器。有已启用的保存机器时，即使 Local 失败或重启，客户端仍可继续使用。

## 连接问题

- **Reconnecting：** 网络中断、睡眠或 SSH 故障后，Herdr 会自动重试。连续失败会将间隔增加到最多两分钟，短暂连接成功不会重置间隔。连接稳定一分钟后，下一次中断才会恢复快速重试。SSH 连接会监测应用层活动并在空闲时探测，避免已断开的连接一直显示 Online。Local 使用本地连接关闭或失败来判断断线，而不是远程健康探测。
- **Attention：** 目标需要认证、批准主机密钥或准备兼容服务器等操作。其他机器仍可使用。**`! auth`** 表示认证失败，**`! error`** 表示其他问题。点击徽章可查看错误和 CLI 命令。侧边栏折叠时两者都显示为 `!`。
- **保存机器文件错误：** 目录文件无法读取或内容无效时，当前连接保持不变。Herdr 会显示通知并自动重试读取。

在侧边栏中，远程机器的名称前带有 `⇄`，Local 没有。已连接的机器不显示其他内容；否则机器行会显示 **connecting…** 或 **reconnecting…**（黄色）、**disabled**（暗色；已停止、已挂起或已隐藏的 hangar 机器也显示为此），或 **`! error`** / **`! auth`**。侧边栏折叠时，连接中和重连中显示为 `…`。机器状态从不使用圆点或圆圈，它们专用于 Agent 状态。

当两端都支持空闲桥接清理时，连接 Linux/macOS 的保存机器会在双向均无流量一分钟后关闭远程桥接。睡眠时间也计入期限，并在唤醒时检查。正常的空闲连接会交换健康检查，持续查看输出无需键盘输入。清理不会停止远程 Herdr 服务器、会话或窗格进程。旧安装仍可兼容连接，只是不使用这项可选清理功能。

后台连接不会回答提示，也不会安装、更新、重启或交接服务器。对于非认证类 Attention，请在交互式终端运行 Herdr 显示的独立设置命令，例如：

```bash
herdr --remote workbox
```

使用配置中的目标。如果添加时选择了命名会话，再加上 `--session <name>`。完成设置后，已打开的客户端会自动重试。`machine reconnect` 不会安装或更新 Herdr。不要仅因为版本与客户端不同就停止运行中的服务器。

认证失败时，先检查普通 SSH。对于有口令的私钥，请在启动 Herdr 的非交互式后台连接前用 `ssh-add` 加载。

如需在远程窗格中进行 Git 认证或 SSH 签名，请在 SSH 配置中为可信主机启用 `ForwardAgent yes`。Herdr 不会替你启用转发。如果会话启动时带有智能体，更新后的 Linux 和 macOS 服务器会为窗格提供稳定的智能体地址，因此在 `--remote` 或已保存机器重新连接后，现有窗格和新窗格都能使用转发的智能体。可用的继承智能体或较早的连接优先于后续客户端和临时设置检查；如果它消失，另一个实时连接可以提供智能体。

这需要更新远程服务器，而不只是本地客户端。未带智能体启动的本地会话不会更改 `SSH_AUTH_SOCK`。在服务器更新前或会话首次获得智能体前创建的窗格会保留原来的环境，需要重新创建一次才能继承稳定地址。较旧的兼容服务器和未转发智能体的连接仍可正常连接。

## 设置与自动化

UI 默认使用客户端本地的主题、侧边栏设置和按键绑定。选中服务器公布的自定义命令和插件仍在那里运行。Herdr 不会将本地插件、配置、可执行文件或机密复制到 SSH 主机。远程缺少命令时会明确报错。编辑客户端设置后，使用 UI 中的 `reload config`；参见[配置](/zh-cn/docs/configuration/)。

有多台机器时，默认智能体行会显示 `machine` token。已有的自定义行保持不变；需要机器标签时请显式加入 `machine`。[侧边栏行布局](/zh-cn/docs/configuration/)还支持按机器标签设置条件颜色。

工作区、标签页、窗格 ID 和智能体名称仅在所属服务器内有效。两台机器可能都有 `w1:p1` 或名为 `reviewer` 的智能体。在 UI 中选择机器不会改变已有窗格中 CLI 命令的目标，它们仍使用继承的会话和 socket。远程自动化可使用 `herdr --machine <label-or-id> agent list` 获取 ID，并在后续操作中使用同一前缀。CLI 直接使用保存的 SSH 目标和会话，不需要打开 TUI。省略 `--machine` 时现有行为不变。支持的命令、更新要求和远程路径规则见 [CLI 参考](/zh-cn/docs/cli-reference/)。

## 更新与保存的数据

配置只保存不透明 ID、标签、SSH 目标、明确的远程会话名和启用状态。Herdr 不会将密码、私钥、智能体票据或 SSH 控制套接字存入机器目录。认证仍由 OpenSSH 处理。

Herdr 会另外记住每台机器的远程操作系统和解析后的可执行文件路径，让重复的 `--machine` 命令可以跳过发现。现有配置会在首次使用时补充缺失信息。该缓存是可选的：缓存文件缺失、无效或不可写都不会妨碍命令运行。命令仍会检查实时服务器兼容性。如果缓存的可执行文件不存在或不再支持 API 转发，Herdr 会在最初的只读检查期间重新发现它；对于可能已经更改远程状态的命令，Herdr 绝不会自动重试。

客户端与服务器协商兼容性，不要求版本完全相同。保存机器的连接还需要服务器支持 `surface_interest` 和 `health_check` 能力。缺少这些能力的旧服务器，即使能独立连接，也会显示 Attention，直到明确更新。其他缺失的方法只禁用对应操作。

更新兼容客户端不会替换远程服务器或停止其智能体。需要新的服务器行为时，请明确更新该服务器。正常替换会在停止服务器及其窗格进程之前询问。

实时交接是实验性的，需要明确选择。独立设置过程中需要替换受支持的服务器时，可为 `herdr --remote` 显式添加 `--handoff`；正常连接或认证修复不需要它。有关重启和交接的选择，请参阅[更新](/zh-cn/docs/install/)及[会话状态与恢复](/zh-cn/docs/session-state/)。
